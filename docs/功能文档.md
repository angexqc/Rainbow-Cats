# Rainbow Cats 情侣点餐小程序功能文档

## 1. 文档信息

- 产品：Rainbow Cats 微信小程序
- 形态：原生微信小程序 + Node API
- 适用范围：`miniprogram/` 当前主线功能
- 后端入口：`../node-api/`
- 默认接口：`https://wubaihappyfood.top/api`
- 本地接口：`http://127.0.0.1:3100/api`

本文档根据当前代码、页面注册表和接口封装整理，描述已实现功能及主要交互流程。未列出的旧版 `pages_legacy/` 与微信云开发云函数不属于当前主线。

## 2. 用户角色与模式

### 2.1 用户角色

- 未配对用户：可独立维护菜单、购物车和订单。
- 已配对用户：可查看双方菜单与订单，并根据创建人区分“我/对方”。
- 管理员：除普通能力外，可管理首页轮播图；通知模板修改受管理员权限限制。

### 2.2 运行模式

- 发布版默认使用 HTTPS 生产 API。
- 微信开发者工具 `develop` 环境在未指定自定义地址时使用本机 API。
- 请求统一携带 JWT；收到登录失效响应时自动静默重新登录并重试一次。
- 查询类场景在网络不可用或服务端 5xx 时可回退到本地 `mockStore`；写入类场景直接报告错误。

## 3. 功能模块

### 3.1 启动与资料

1. 启动页检查登录态、资料完整度和配对状态。
2. 微信登录通过 `wx.login` 获取 code，换取 Node API JWT。
3. 资料页支持昵称填写、微信昵称回填、头像选择/上传和保存。
4. 资料保存成功后返回来源页面；首次使用可进入单人模式或配对流程。

### 3.2 首页

- 展示首页轮播图、当前周期菜品排行和最受欢迎菜品。
- 支持周/月/年排行切换。
- 支持从热门菜品直接加入购物车，并提供数量增减。
- 提供配对入口、菜单入口、随机点餐入口和购物车入口。
- 支持微信好友分享和朋友圈分享。

### 3.3 情侣配对

- 查看当前配对状态、对方昵称和头像。
- 生成 8 位配对码。
- 手动输入或扫码识别配对码并绑定。
- 绑定后轮询配对状态，成功后回到首页。
- 支持解除绑定；解除绑定属于危险操作，需要二次确认。
- 允许跳过配对，以单人模式使用。

### 3.4 菜单与分类

- 菜单列表支持关键词搜索、分类筛选、创建人筛选、下拉刷新和分页加载。
- 已配对时可筛选“全部/我/对方”；服务端优先执行 owner 过滤。
- 菜单详情支持查看图片、描述、分类和上下架状态。
- 菜单新增/编辑支持名称、描述、分类、图片和可售状态。
- 菜单删除、下架等有影响的操作需要确认。
- 分类管理支持新增、编辑、删除、拖拽排序和恢复默认；“其他”不可删除。
- 菜品可直接加入购物车，列表中可调整数量。

### 3.5 购物车与随机点餐

- 购物车按“用户 + 配对会话”隔离存储，兼容迁移旧版 `cart` 数据。
- 支持全选、单选、增加数量、减少数量、删除选中项和清空购物车。
- 选中部分菜品后进入订单确认页，可填写备注。
- 随机点餐页从当前可售菜单最多取 80 道菜，转盘随机选择一道。
- 转盘结果可重新抽取或加入购物车。
- 提交订单时生成幂等键，确认页成功创建订单后才清理已下单菜品和 checkout 数据。

### 3.6 订单

- 订单历史支持状态筛选、分页、下拉刷新和按日期查看。
- 订单详情展示订单编号、菜品明细、时间线、创建人和当前状态。
- 订单状态流转：创建、确认、完成、取消；创建者与配对方拥有不同操作权限。
- 支持订单菜品再次加入购物车。
- 支持点赞和文字评价。
- 评价文本当前最多 200 字。

### 3.7 订阅通知

- 查看通知开关、模板配置和微信身份绑定状态。
- 通过微信订阅消息授权开启下单通知。
- 支持绑定微信 session、选择/保存订单创建模板和发送测试通知。
- 通知授权失败不阻断订单创建，但会向用户提示原因。

### 3.8 图片上传与分享

- 图片上传统一走 `/upload/image`，支持菜单图、轮播图和头像。
- 生产上传地址必须为 HTTPS；本地调试仅允许 localhost/127.0.0.1 的 HTTP 地址。
- 页面通过统一分享工具生成好友分享和朋友圈分享参数。

## 4. 关键业务流程

### 4.1 登录与进入首页

`启动页 -> wx.login -> /auth/login -> 保存 JWT -> /auth/me -> 资料检查 -> 配对检查 -> 首页`

### 4.2 菜单点单

`菜单/首页 -> 加入购物车 -> 购物车作用域存储 -> 选择菜品 -> 订单确认 -> 订阅授权（可选） -> /orders -> 清理已下单项 -> 订单历史`

### 4.3 配对

`配对页 -> 生成或输入配对码 -> /pair/code 或 /pair/bind -> 配对状态刷新 -> 菜单/订单按双方关系展示`

### 4.4 订单协作

`订单历史 -> 订单详情 -> 创建者取消 / 对方确认 / 对方完成 -> /orders/:id/status -> 时间线刷新`

## 6. 数据与权限约束

- JWT 存储键：`authToken`；用户缓存键：`authUser`。
- 购物车键由 `cartStore` 根据用户 ID 与配对会话生成，避免不同关系串单。
- 菜单、订单查询在服务端已返回用户范围数据时信任后端；否则由 `apiStore` 做本地作用域过滤。
- 创建、编辑、删除菜单和订单状态变更均经 Node API 鉴权与参数校验。
- 管理员专属能力由后端权限中间件最终裁决，前端提示不能替代后端鉴权。

## 7. 已知实现注意事项

- 订单确认页不信任购物车中的菜品状态缓存；最终有效性由后端按真实菜品快照校验，菜品下架或删除时返回明确错误并保留购物车。
- 配对码具有服务端有效期和状态；过期或已使用的配对码需要重新生成。
- `docs/` 中的设计稿用于产品参考，功能行为以页面代码和 Node API 路由为准。

## 8. 验证建议

- 前端：在 `miniprogram/` 执行 `npm test`。
- 后端：在 `../node-api/` 执行项目既有测试与 test gate。
- 手工验收至少覆盖：首次登录、单人/配对切换、菜单增删改、购物车部分下单、随机点餐、订单状态流转、通知授权拒绝和图片上传。
