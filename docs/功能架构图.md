## 核心数据流

```mermaid
sequenceDiagram
  participant Page as 页面
  participant Store as apiStore/cartStore
  participant HTTP as http.js
  participant API as Node API
  participant DB as 数据库

  Page->>Store: 查询或提交业务动作
  Store->>HTTP: 调用领域 service
  HTTP->>HTTP: 读取 JWT、拼接 API Base
  HTTP->>API: HTTPS/本地 HTTP 请求
  API->>DB: 鉴权、校验、读写数据
  DB-->>API: 业务结果
  API-->>HTTP: { code, data, message }
  HTTP-->>Store: data 或错误
  Store-->>Page: 更新页面状态
```

## 订单状态与权限

```mermaid
stateDiagram-v2
  [*] --> pending: 创建订单
  pending --> confirmed: 配对方确认
  pending --> cancelled: 创建者取消
  confirmed --> completed: 配对方完成
  confirmed --> cancelled: 创建者取消
  completed --> [*]
  cancelled --> [*]
```

权限规则：创建者可取消 `pending/confirmed` 订单；配对方可将 `pending` 确认、将 `confirmed` 完成；服务端负责最终鉴权。

## 分层职责

| 层 | 目录/组件 | 职责 |
| --- | --- | --- |
| 交互层 | `miniprogram/pages/` | 页面状态、用户输入、导航和提示 |
| 状态与聚合层 | `miniprogram/utils/apiStore.js` | 统一业务入口、作用域过滤、查询回退 |
| 本地状态层 | `miniprogram/utils/cartStore.js`、`identity.js` | 购物车、checkout、身份和配对上下文 |
| 接口层 | `miniprogram/services/*.js` | 将业务动作映射为 HTTP 请求 |
| 通信层 | `miniprogram/services/http.js` | API 地址、JWT、自动重登录、错误提示 |
| 后端路由层 | `../node-api/src/routes/` | 鉴权、参数校验、业务路由 |
| 持久化层 | Node API repository / DB | 用户、配对、菜单、订单、分类和通知数据 |
| 外部能力 | 微信 API、上传存储 | 登录、订阅消息、图片文件 |
