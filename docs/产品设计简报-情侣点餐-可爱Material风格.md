# 情侣点餐小程序 UI 设计简报

## 1. 文档目的

本文档基于当前项目代码中的页面、字段和交互抽取整理，供 UI 设计师进行界面设计。文档只描述当前小程序已经具备或代码中已体现的功能，不扩展当前实现之外的业务能力。

## 2. 产品定位

**产品名称**：Rainbow Cats 情侣点餐

**产品类型**：微信小程序情侣点餐与菜单管理工具

**核心目标**：帮助情侣双方建立关联后，共同维护菜品菜单、添加菜品到购物车、创建订单、查看点餐历史，并通过随机点餐、排行榜、点赞评价等方式让日常点餐更轻松可爱。

**设计风格**：可爱的 Material 风格。界面需要有 Material 的清晰层级、卡片、轻阴影、按钮反馈和状态标签，同时加入猫咪、食物、情侣陪伴感等可爱元素。整体应清爽、温柔、易操作。

## 3. 当前导航结构

当前 `app.json` 中 TabBar 为 5 个入口：

| Tab | 页面路径 | 当前功能 |
| --- | --- | --- |
| 首页 | `pages/Home/index` | 轮播图、点单排行、最受欢迎菜品、去点单 |
| 菜单 | `pages/Menu/Menu` | 菜品搜索、分类筛选、归属筛选、添加菜品、加入购物车 |
| 点单 | `pages/Order/Order` | 购物车管理、批量选择、数量调整、下单 |
| 订单 | `pages/OrderHistory/OrderHistory` | 订单状态筛选、订单时间线、点赞评价、再下一单入口 |
| 我的 | `pages/My/My` | 轮播图管理、分类管理、个人资料、关联管理 |

## 4. 核心业务对象

### 4.1 用户资料

用于展示在菜单创建者、订单时间线等位置。

| 字段 | 界面含义 |
| --- | --- |
| 头像 | 创建者头像、订单操作人头像 |
| 昵称 | 创建者名称、订单操作人名称 |

### 4.2 情侣关联

| 状态 | 界面表现 |
| --- | --- |
| 未配对 | 可生成/展示配对码、输入或扫码绑定、可跳过进入首页 |
| 已配对 | 显示对方头像、昵称、绑定时间，可重新生成配对码、进入首页、解除绑定 |

当前界面中的配对码为 8 位，登录后配对码固定，可长期使用。

### 4.3 菜品

| 字段 | 界面含义 |
| --- | --- |
| 菜品名称 | 菜单列表、详情、购物车、订单明细展示 |
| 菜品图片 | 菜单卡片、详情大图、购物车缩略图、订单明细缩略图 |
| 菜品描述 | 菜品详情展示，可选 |
| 分类 | 筛选、标签、购物车和订单中展示 |
| 创建者 | 菜单列表和详情中展示头像与昵称 |
| 上下架状态 | 详情页可操作，上架后可用于点单 |

### 4.4 购物车

| 字段 | 界面含义 |
| --- | --- |
| 菜品 | 购物车条目 |
| 数量 | 加减器调整 |
| 选中状态 | 批量选择、批量删除 |
| 总份数 | 底部栏和订单中展示 |

### 4.5 订单

| 字段 | 界面含义 |
| --- | --- |
| 订单号 | 订单详情状态卡展示 |
| 菜品明细 | 菜品名称、图片、数量 |
| 总份数 | 订单列表、详情、日历历史展示 |
| 状态 | 待确认、已确认、已完成、已取消 |
| 时间线 | 展示订单创建、确认、完成、取消等流转 |
| 备注 | 订单详情展示 |
| 点赞 | 订单历史和详情中展示 |
| 评价 | 可新增或修改评价 |

## 5. 页面与界面需求

### 5.1 启动页

**页面路径**：`pages/Splash/index`

**设计目标**：作为进入小程序前的轻量加载页，承接可爱猫咪品牌气质。

**设计要点**

- 使用猫咪或食物相关加载动效。
- 保持短暂、轻盈，不做复杂操作。
- 需要兼容后续跳转到资料完善、配对或首页。

### 5.2 完善资料页

**页面路径**：`pages/ProfileSetup/index`

**当前功能**

- 提示用户先设置昵称和头像。
- 支持使用微信头像。
- 支持上传头像。
- 输入昵称，最多 20 字。
- 保存并继续。

**设计要点**

- 头像区域应是视觉中心。
- 上传头像和使用微信头像属于并列操作。
- 保存按钮需要明确可点击状态、保存中状态。

### 5.3 首页

**页面路径**：`pages/Home/index`

**当前功能**

- 顶部杂志感轮播图。
- 文案：`今天也一起好好吃饭`、`情侣每日菜品点单记录`。
- 菜品点单排行，支持周期切换。
- 排行榜菜品可直接下单或用加减器调整数量。
- 展示最受欢迎菜品 TOP 1。
- 底部“去点单”按钮。

**设计模块**

- 顶部轮播 Hero。
- 排行榜卡片。
- 最受欢迎菜品卡片。
- 主要行动按钮。
- 空状态：当前周期无点单数据。

**设计要点**

- 首页应有“每日小报/情侣日常”的温柔氛围。
- 排行榜信息要清楚展示排名、菜名、点单次数、下单按钮。
- 已加入购物车的菜品应显示紧凑加减器。

### 5.4 情侣配对页

**页面路径**：`pages/Pair/Pair`

**未配对状态功能**

- 展示“暂未绑定情侣”提示。
- 展示二维码或二维码生成中状态。
- 展示配对码和复制按钮。
- 输入 8 位配对码。
- 扫码绑定。
- 绑定按钮，根据输入状态启用或禁用。
- 可跳过配对，直接进入首页。

**已配对状态功能**

- 展示对方头像、昵称、绑定时间。
- 重新生成配对码。
- 进入首页。
- 展示当前配对码。
- 解除绑定。

**设计要点**

- 未配对不是错误状态，应做成友好引导。
- 配对码需要高可读性，复制按钮要容易发现。
- 解除绑定是危险操作，应有明显风险层级。

### 5.5 菜单列表页

**页面路径**：`pages/Menu/Menu`

**当前功能**

- 顶部标题：菜单列表。
- 右上角入口：点餐历史日历、购物车、添加菜品。
- 搜索菜品名称。
- 分类筛选。
- 已配对时展示归属筛选。
- 菜品列表展示图片、名称、分类、创建者头像与昵称。
- 菜品可直接“下单”加入购物车。
- 已加入购物车时显示行内加减器。
- 支持下拉刷新、上拉加载更多。
- 空状态可引导添加菜品。
- 加载状态使用猫咪 Lottie。

**设计要点**

- 菜品卡片只强调名称、分类、创建者和点单行为。
- 分类 Chip 和归属 Chip 要有明显区分。
- 顶部固定区域需要清楚但不压迫内容。
- 购物车角标显示当前已选数量。

### 5.6 添加/编辑菜品页

**页面路径**：`pages/MenuAdd/MenuAdd`、`pages/MenuEdit/MenuEdit`

**当前字段**

- 菜品名称，必填，最多 20 字。
- 菜品图片，必填，建议 1:1。
- 菜品描述，选填，最多 100 字。
- 分类，必填，通过 Picker 选择。
- 保存按钮。

**设计要点**

- 表单应简洁，只围绕名称、图片、描述、分类进行设计。
- 上传图片区域需要有明确的空状态、预览状态。
- 必填项用轻量标识，不要造成压力感。
- 保存成功、保存失败需要有 Toast 或提示状态。

### 5.7 菜品详情页

**页面路径**：`pages/MenuDetail/MenuDetail`

**当前功能**

- 查看菜品大图。
- 展示菜名、分类、创建者头像与昵称。
- 展示菜品描述。
- 自己创建的菜品可编辑、删除。
- 菜品可上架或下架。
- 加载状态使用猫咪 Lottie。

**设计要点**

- 大图应作为详情页第一视觉。
- 操作按钮根据权限和状态展示。
- 删除为危险操作，上下架为状态操作，视觉层级需要区分。

### 5.8 购物车页

**页面路径**：`pages/Order/Order`

**当前功能**

- 页面标题：购物车。
- 右上角入口：随机点餐、清空购物车。
- 购物车非空时展示已选项数和总份数。
- 支持全选/取消全选。
- 支持批量删除。
- 购物车条目展示分类、选中状态、图片、名称、数量加减器、单项删除。
- 底部栏展示总份数和“下单”按钮。
- 空状态提示可去随机点餐或菜单页添加菜品。

**设计要点**

- 购物车以菜品数量和总份数为核心。
- 批量操作区需要清晰表达“选中”和“删除”的关系。
- 空状态可以更可爱，但需要保留明确路径：随机点餐 / 菜单页添加。

### 5.9 随机点餐页

**页面路径**：`pages/OrderWheel/OrderWheel`

**当前功能**

- Hero 文案：`不知道吃什么？让小猫帮你转一个`。
- 从当前可点菜单随机抽一道。
- 展示可选菜品数量。
- 支持换一批。
- 转盘开始转、加载中、转动中状态。
- 展示抽中的菜品图片、名称、分类。
- 支持加入购物车或再转一次。

**设计要点**

- 转盘是核心娱乐组件，应保留轻松、可爱的仪式感。
- 动效要清楚表达“正在随机”和“已抽中”。
- “加入购物车”是主操作，“再转一次”为次操作。

### 5.10 订单历史页

**页面路径**：`pages/OrderHistory/OrderHistory`

**当前功能**

- 状态筛选：全部、待确认、已确认、已完成、已取消。
- 订单卡片展示时间、状态标签、菜品摘要、订单时间线、总份数。
- 支持点赞或取消点赞。
- 支持评价或修改评价。
- 已评价订单展示评价内容。
- 支持下拉刷新、上拉加载更多。
- 空状态：暂无订单记录。

**设计要点**

- 订单状态标签需要统一颜色体系。
- 时间线应清楚展示状态变化、操作人头像/昵称和时间。
- 点赞与评价是轻互动功能，不要抢主信息层级。

### 5.11 订单详情页

**页面路径**：`pages/OrderDetail/OrderDetail`

**当前功能**

- 展示订单状态和订单号。
- 展示订单进度时间线。
- 展示菜品明细：图片、名称、数量。
- 展示合计份数。
- 有备注时展示备注。
- 点赞与评价。
- 支持再下一单。
- 根据订单状态展示取消、确认、完成等操作按钮。

**设计要点**

- 状态卡片应放在顶部，帮助用户快速理解订单状态。
- 菜品明细以菜品图片、名称和数量为核心。
- 底部操作按钮应根据当前状态有明确主次关系。

### 5.12 点餐历史日历页

**页面路径**：`pages/MenuHistory/MenuHistory`

**当前功能**

- 月份切换。
- 日历展示有点餐记录的日期、记录数量、今天、选中态。
- 展示选中日期的订单列表。
- 订单条目展示时间、状态、菜品摘要、总份数。
- 支持再下一单。
- 加载状态使用猫咪 Lottie。

**设计要点**

- 日期有记录时的标记需要明显但轻量。
- 日历与当天记录列表之间要有清晰关系。
- 适合使用可爱贴纸式小圆点，但不要影响日期可读性。

### 5.13 我的页

**页面路径**：`pages/My/My`

**当前功能**

- 轮播图管理：展示当前数量、轮播预览、删除、上传轮播图。
- 菜品分类管理：新增分类、编辑分类、删除分类、拖拽排序、恢复默认分类。
- 个人资料：进入资料编辑。
- 关联管理：未配对时去配对，已配对时解除关联。

**设计要点**

- 我的页偏管理后台，但仍保持可爱 Material 风格。
- 分类拖拽排序需要让拖拽手柄和排序反馈清楚。
- 删除分类、解除关联是危险操作，需要明显但克制。

## 6. 订单状态设计

| 状态 | 文案 | 建议颜色 | 可用操作 |
| --- | --- | --- | --- |
| `pending` | 待确认 | 蜜橙色 | 接收方确认，相关用户可取消 |
| `confirmed` | 已确认 | Material 蓝 | 可完成，可取消 |
| `completed` | 已完成 | 清新绿 | 只读、再下一单、评价 |
| `cancelled` | 已取消 | 中性灰 | 只读、再下一单、评价 |

设计时需确保列表页、详情页、日历页中的状态颜色和文案一致。

## 7. 可爱 Material 视觉规范

### 7.1 关键词

- 可爱
- 温柔
- 食物感
- 猫咪陪伴
- 卡片层级
- 清楚反馈
- 轻管理

### 7.2 色彩建议

| 用途 | 建议色 | 说明 |
| --- | --- | --- |
| 主色 | `#FF8FA3` | 樱桃粉，用于主按钮和高亮 |
| 主色深 | `#F25F7A` | 按压态、重点强调 |
| 辅助色 | `#6EC6B8` | 薄荷绿，用于成功状态 |
| 点缀色 | `#FFD166` | 奶油黄，用于徽章、排行、食物氛围 |
| 信息色 | `#5C7CFA` | 已确认、信息提示 |
| 背景色 | `#FFF7F9` | 页面底色 |
| 卡片色 | `#FFFFFF` | 内容承载 |
| 主文本 | `#2B2B2F` | 标题和正文 |
| 次文本 | `#7B7D86` | 描述和辅助信息 |
| 分割线 | `#F0E6EA` | 轻分割 |

### 7.3 组件规范

- 卡片：8-12px 圆角，轻阴影，避免厚重拟物。
- 主按钮：粉色填充，适用于保存、绑定、下单、确认、加入购物车。
- 次按钮：浅底或描边，适用于返回首页、再转一次、恢复默认。
- 危险按钮：红色或浅红底，适用于删除、清空、解除关联、取消订单。
- Chip：用于分类、归属、状态筛选，选中态要明显。
- 加减器：圆形或小胶囊按钮，数字宽度固定，减少跳动。
- 状态标签：小胶囊 Badge，订单状态颜色全局统一。
- 加载态：复用猫咪 Lottie，保持品牌一致。

### 7.4 图形与插画

- 可使用猫咪、饭团、奶茶、餐盘、爪印、爱心等元素。
- 插画适合放在空状态、加载状态、随机点餐页和配对引导页。
- 菜品图片优先使用用户上传图片；无图时才使用缺省插画。
- TabBar 已使用猫咪图片，设计稿需要保持选中态足够清晰。

## 8. 交互与动效建议

- 按钮点击保留 Material 的轻反馈，例如水波纹、轻微缩放或颜色变化。
- 菜品加入购物车时，按钮切换为加减器要顺滑。
- 随机转盘需要有明显转动、减速、选中反馈。
- 点赞可以有轻微弹跳或填充动画。
- 分类拖拽排序需要提供拖动中、目标位置、松手完成反馈。
- 删除、清空、解除关联、取消订单必须有二次确认。

- 菜品详情页
- 购物车页：空购物车、非空购物车、批量选择

- 订单历史页
- 订单详情页：四种状态

- 图片上传失败
- 网络异常
- 下拉刷新和加载更多
- 评价输入弹窗
- 删除/取消/解除关联确认弹窗

## 10. 文案基调

文案应短、轻松、亲密，不使用商业化或交易感强的表达。

**建议示例**

- 空菜单：`还没有菜品，先加一道想吃的吧`
- 空购物车：`购物车还是空的，让小猫帮你转一道？`
- 随机点餐：`不知道吃什么？让小猫帮你转一个`
- 下单成功：`已经放进今天的点餐记录啦`
- 绑定引导：`绑定 TA 之后，就可以共享菜单和一起点餐啦`
- 删除确认：`确定删除这道菜吗？`
- 清空确认：`确定清空购物车吗？`
- 评价入口：`这单吃得怎么样？`

## 11. 设计验收标准

- 设计稿只呈现当前代码中已有的业务信息和界面状态。
- 菜单、购物车、订单统一以“数量/份数”为核心统计。
- 首页、菜单、购物车、订单、我的五个 Tab 的功能边界清楚。
- 订单状态在列表、详情、日历中颜色和文案保持一致。
- 用户能清楚识别菜品分类、创建者、购物车数量、订单状态。
- 空状态、加载态、异常态都有对应设计。
- 可爱元素服务于情绪和引导，不影响信息识别和触控效率。
- 主要触控区域不小于 44px，适配微信小程序手机端使用。
